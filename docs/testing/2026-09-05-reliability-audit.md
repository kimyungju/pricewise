# Pricewise 오류 경계 점검

## 수정 및 검증

| 경계 | 재현한 문제 | 수정 |
|---|---|---|
| 모델 출력 | 잘못된 JSON, 잘못된 action, null profile_patch/candidates, 빈 응답 | 검증 실패 시 해당 모델 호출만 한 번 재시도. 반복 실패는 종료 안내. 도구 실행은 재시도하지 않음 |
| 누락된 근거 | currency 및 assessment.quote의 null이 파싱 실패 | 미확인 값 허용. 근거 없는 가격·속성은 하드 조건을 통과하지 못함 |
| 도구 인자 | 빈 위임 목록의 max_workers=0 충돌, 음수·NaN·무한 가격, 0 이하 결과 개수 | 실행 전 스키마 검증 |
| SSE | 네트워크 청크 경계에서 이벤트명 소실, 한국어 UTF-8 분할, 조기 종료 | 프레임 단위 파싱, 런타임 이벤트 검증, 종료/취소 처리 |
| 응답 화면 | done이 승인 대기/오류를 덮음, 실패 후 빈 Composing 잔류 | 최종 상태 유지 및 읽을 수 있는 오류 표시 |
| 도구 카드 | 승인 재개 결과가 이전 카드에 붙지 않음 | 완성된 호출 이벤트와 호출 ID로 결과 연결 |
| 승인 복구 | 새로고침 시 승인 버튼 소실, 오래된 승인 재전송 | GET 이력에 pending_approval 제공, interrupt ID 검증 |
| 세션 쓰기 | 동시에 보낸 메시지/승인이 같은 상태를 변경 | 현재 단일 ASGI worker에서 스트림 종료까지 세션별 쓰기 차단(409), 종료·실패 시 해제 |
| 입력 경계 | 공백 메시지, 문자열 승인값, 승인 대기 중 새 메시지 | 422/409로 실행 전 거절 |
| 저장소·네트워크 | 일시 장애를 세션 삭제로 처리, 늦은 이력이 New chat을 덮음 | 503과 실제 404 구분, 기존 세션 보존, 취소된 요청의 상태 변경 방지 |
| 공개 응답 | 내부 예외 원문 노출, content block 배열이 이력 UI 파싱 실패 | 안전한 오류 메시지와 문자열 이력 전달 |

## 검증 근거

- Python 전체 pytest **157개 통과**. 기존 126개에서 31개 오류 경계 테스트 추가.
- 프런트엔드 Vitest **21개 통과**. 모든 바이트 분할 위치, 멀티바이트 문자, 잘못된/불완전한 이벤트, 승인 복원, 중복 요청, 취소 경쟁 포함.
- Ruff, 변경한 백엔드 모듈 BasedPyright 오류 검사, 프런트엔드 TypeScript, Next 프로덕션 빌드 통과.
- 실제 OpenAI/Tavily를 사용하는 로컬 프로덕션 브라우저에서 검색 → 승인 대기 → 새로고침 → 승인 복원 → 검색 결과/도구 결과 표시 → 두 번째 검색 거절 → 입력 재활성화를 확인. 브라우저 오류 로그 없음.
- GitHub CI에 프런트엔드 테스트·타입 검사·빌드를 추가해 이후 변경도 검사한다.

## 범위와 한계

외부 모델·검색 API·네트워크 장애 자체가 발생하지 않는다는 보장은 아니다. 이번 검사는 실패가 무한 대기, 상태 손상, 잘못된 승인 또는 근거 없는 가격 확정으로 이어지지 않도록 하는 데 집중했다. 자동 재시도도 실패하면 사용자에게 재요청 안내를 표시한다. 세션 동시성 보호는 현재 서비스의 단일 worker 배치에 적용되며, 다중 프로세스/복제본 전환 시 공유 저장소 기반 잠금이 필요하다. 추천 품질이나 후회 확률의 정량 평가는 별도다.
